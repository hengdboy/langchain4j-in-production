# 实验室（Labs）：5 个小业务场景，把 12 章练成自己的

每个 lab 是一个**独立的 Maven 模块**，从空目录搭起，不依赖主项目的代码。读者跟完全书改过一个大项目，但没从零搭过一个自己的——这层"自己动手、规模可控"的台阶就是 labs 存在的意义。

## 统一验收三件套

做完每个 lab，交这三样——它们比"代码能跑"重要：

1. **小金标集**（每 lab 已带 6–10 题）：把 Ch13 的"评估优先"变成肌肉记忆。你改进了任何东西，先跑金标再说话；
2. **成本报表**：每个 lab 用了多少次模型调用、按 Ch22 实测单价折算约多少钱（各 README 给了当次实测的数字）。不算钱的优化都是纸上谈兵；
3. **踩坑记录**：每个 README 末尾都有作者当天的真实踩坑（保证金算错被测试抓、`-parameters` 没开导致工具参数名变 arg1……）。你踩到的新坑记下来，做得好可以提 PR 进仓库。

## 怎么跑

```bash
cd labs
mvn test                          # 全部 5 个 lab 的离线测试，不需要任何 API key
mvn test -pl lab1-contract-qa     # 单独跑一个 lab

# 在线实测（需要 key，二选一配环境变量）
export DEEPSEEK_API_KEY=sk-xxx    # 或 OPENAI_API_KEY
# 各 lab 的在线命令见各自 README
```

测试全部离线可跑：检索评估用本地 ONNX 嵌入模型，LLM 相关逻辑用桩模型（`StubChatModel`，40 行，按剧本回放）逼到边界。**离线测试保证"代码是对的"，在线实测给出"真实效果数字"——两层缺一不可。**

## 版本与环境

与主教程同口径：LangChain4j `1.22.0` + 实验模块 `1.22.0-beta32`、JDK 21（enforcer 强制）、JUnit 5。语料全部虚构（合同/公告/简历均为编造数据，规避隐私问题），业务规则取自真实场景常识。
